## 우선 수정할 항목

### 1. P1 — ‘보관’과 실제 삭제 동작을 일치시켜야 한다

- 운영자 결과의 **결과 정리**를 누르면 제목은 ‘결과를 내보내고 보관할까요?’지만 본문은 원문·추출 결과 삭제를 안내한다. 실제 동작에는 자동 내보내기가 없다. 이 점검에서는 삭제 확인을 누르지 않았다.
- 개인 이용 내역의 **목록에서 보관**은 코드상 별도 확인 없이 같은 `archive`를 호출한다. 개인 화면에는 결과 내보내기나 보관함 진입이 없다. 개인 완료 기록 화면은 이번 브라우저 점검에서 재현하지 않았고 코드로 확인했다.
- 기존 테스트를 실행하여 `archive` 후 프롬프트 `messages`와 답변 `tasks[0].output`이 삭제됨을 확인했다.
- 최소 개선: ‘원문·답변 삭제’처럼 실제 동작을 명시하고 개인 화면에도 확인 단계를 둔다. 결과 저장을 제공한다면 **저장**과 **삭제**를 별도 동작으로 구분한다. ‘보관함’ 전체를 새로 만들 필요는 없다.
- 위치: `app/participant-panel.tsx:456`, `app/page.tsx:1984`, `lib/relay/engine.mjs:269`, `tests/chat-jobs.test.mjs:119`.

### 2. P2 — 같은 ‘작업 생성’ 진입점이 서로 다른 준비 조건을 적용한다

- 재현: 실제 실행에서 승인 모델이 없는 상태 → 작업 → 빈 목록의 **작업 만들기**.
- 모델 목록이 비어 있고 **작업 실행**은 비활성인 생성 폼이 열린다. 사용자가 폼 안에서 문제를 해결할 경로가 없다.
- 같은 상태에서 상단 **새 작업**은 정상적으로 시작하기 화면에 보낸다.
- 최소 개선: 기존 준비 조건 검사를 모든 생성 진입점에서 재사용한다. 모델이 없으면 모델 준비로 연결하고, 폼 내부에도 필요한 준비를 설명한다.

### 3. P2 — 서버가 끊겨도 ‘스케줄러 연결됨’으로 표시한다

### 8. P2 — 개인 메뉴의 탭을 방향키로 이동할 수 없다

- 재현: 개인 화면의 **이용·수익 내역** 탭에 초점을 둔 후 왼쪽 방향키.

### 9. P3 — 준비 안 된 기능의 다음 행동과 용어를 정리해야 한다

- **분산 LLM**: 그룹이 없다는 설명은 있지만 설정 문서나 준비 단계로 연결하는 버튼이 없다. 현재는 운영자가 구성 파일로 준비해야 하므로 그 경로를 직접 안내하면 된다.

## 코드에서 발견했으나 추가 재현이 필요한 항목

- **하단 작업 실패 안내**: 개인 화면의 일반 오류/성공 안내는 모달 맨 위에만 렌더링된다(`app/participant-panel.tsx:319`). GPU 등록 오류와 달리 초점 이동이 없어 하단에서 업로드 실패 시 메시지를 못 볼 가능성이 있다. 파일 선택 자동화가 거부되어 이번에는 실패 업로드 재현을 완료하지 못했다.
- **허용 제공자와 모델 불일치**: 새 문서 작업에서 제공자 목록은 폐기 여부만 거르고 선택 모델과의 호환성은 필터링하지 않는다(`app/page.tsx:1774`). 배정은 모델 일치를 요구하므로 다른 모델 노드만 선택한 경우 대기가 길어질 수 있다. 서로 다른 모델의 실제 제공자 두 대로 재현해야 한다.
- **분산 대화/연결 키 보존**: 다른 메뉴로 이동하면 컴포넌트가 해제되는 구조다. 구성된 분산 실행 공간이 없어 대화·키 저장과 화면 이탈을 실제로 검증하지 않았다.

## 권장 작업 순서와 재확인 기준

1. 보관/삭제 문구와 확인 흐름: 결과를 잃는 동작을 사용자가 명확히 이해하고 취소할 수 있어야 한다.
2. 작업 생성 조건·GPU 이용 가능 상태·빈 목록: 시작 버튼을 어디서 누르든 같은 준비 화면으로 이어져야 한다.
3. 주소 이동·네트워크 상태·검색 상태: 화면의 상태가 실제 상태를 그대로 설명해야 한다.
4. 모바일 헤더·개인 탭·긴 모달: 390px에서 현재 화면명, 닫기, 다음 행동이 읽히고 키보드 이동이 되어야 한다.
5. 분산 기능 준비 안내와 파일 용어: 사용자에게 필요한 다음 행동을 같은 표현으로 전달해야 한다.

공통 진입 함수와 기존 UI 컴포넌트, CSS 수정으로 먼저 해결할 수 있다. 새로운 상태 관리 라이브러리나 대규모 컴포넌트 분할을 선행할 필요는 없다.

## 검증의 한계

실제 GGUF 업로드·GPU 적재·LLM 답변·VRAM 회수, PC 도우미 네이티브 창, 분산 그룹의 생성·장애 복구는 이번 점검에서 검증하지 않았다. 실제 하드웨어 성능이나 배포 서버의 안정성을 확인한 결과로 해석하면 안 된다. 복구 파일과 연결 파일은 다운로드 요청 및 UI 전환까지 확인했으며 복원/재연결은 검증하지 않았다.

스크린샷 21개는 `work/ux-audit-20260922/screenshots`에 있으며 로컬 점검 자료다. `work`는 Git 제외 경로이므로 이 보고서를 다른 환경에 공유할 때는 필요한 이미지를 함께 전달해야 한다.

## 개선 반영과 재검증

2026-09-22 후속 요청에 따라 다음을 수정했다. 기존 컴포넌트와 CSS를 사용했으며 의존성을 추가하지 않았다.

| 발견 항목 | 반영 결과 |
|---|---|
| 1. 보관/삭제 혼동 | 실제 동작에 맞춰 원문·답변/결과 삭제로 표시한다. 개인 내역에 결과 JSON 저장과 영구 삭제 확인창을 추가했다. 운영자 확인창에도 삭제 범위와 복구 불가를 설명하고, 실패하면 확인창을 유지한다. |
| 2. 모델 없이 작업 생성 | 모든 새 작업 진입점이 공통으로 모델 준비 상태를 확인하고 시작하기 화면으로 안내한다. 체험 진입은 유지한다. |
| 3. 잘못된 연결 상태 | 연결 확인 중·연결됨·연결 끊김을 구분한다. 끊긴 경우 마지막 갱신 시각과 기존 데이터를 유지하고, 한국어 오류 및 재연결 동작을 제공한다. |
| 4. 모바일 헤더 | 중복 진입 버튼을 제거하고 화면명을 한 줄로 표시한다. 390px에서 글자가 세로로 흩어지거나 헤더를 벗어나지 않는다. |
| 5. 뒤로 가기 | 주소의 개인 화면 해시가 없어지면 창을 닫고, 앞으로 가기로 다시 연다. |
| 6. 검색 결과 없음 | 첫 작업 안내와 구분해 검색 결과 없음 및 검색어 지우기를 표시한다. |
| 7. GPU 없는 긴 입력 화면 | 실행 가능한 GPU를 먼저 선택하도록 안내한다. GPU가 사라져도 작성한 내용·업로드 모델·기존 결과는 유지한다. 개인 창은 내부만 스크롤하고 제목·닫기 및 탭은 접근 가능한 위치에 둔다. |
| 8. 개인 탭 접근성 | 기존 Radix 탭을 사용해 방향키 이동, 선택 상태, 연결된 패널을 제공한다. |
| 9. 준비 안내와 용어 | 실행 환경 확인 파일로 명칭을 통일하고 GPU만 제공하는 흐름의 불필요한 모델명 입력을 숨긴다. 분산 LLM 준비 단계·저장소 문서/설정 경로·재확인을 제공하고 서비스 범위 설명을 갱신한다. |

추가 확인 항목도 보완했다.

- 개인 화면의 일반 오류는 초점을 이동하고 스크롤해 보이게 한다. 실제 파일 업로드가 포함된 브라우저 검사에서 오류 안내를 확인했다.
- 문서 작업의 허용 제공자는 선택 모델과 일치하는 노드만 보여준다. 모델 변경 시 선택을 초기화하고 제출 시에도 유효성을 확인한다. 선택한 노드가 폐기된 경우 사용자가 명시적으로 선택을 초기화할 수 있으며 작성 내용은 보존한다.
- 분산 LLM 화면은 메뉴 이동 중 유지해 연결 키·작성 중 메시지·대화가 사라지지 않게 한다. 새로고침 및 로그아웃 시 초기화되는 범위도 설명한다.
