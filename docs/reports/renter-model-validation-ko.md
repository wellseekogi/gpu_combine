# 임차인 업로드 모델 실행 검증

2026-09-19, 테스트 전용 기록. 운영 배포는 수행하지 않았다.

## 검증 범위

동일한 Windows 컴퓨터에서 격리한 Relay 서버, 합성 회원 2명, GPU 전용 제공자를 실행했다. 운영 DB는 사용하지 않았으며 기존 모델 프로세스도 중지하지 않았다. 제공자는 자체 모델 없이 실행하고 임차인이 업로드한 모델만 내려받았다.

| 모델 | `Qwen3-4B-Instruct-2507.Q3_K_M.gguf` |
| 파일 크기 | 2,075,617,728바이트 |
| 모델 SHA-256 | `42fd3a1a10a371d1a926ac7dee7e33d4b4389ddde7a0282f788849a0b979f8f8` |
| 실행 조건 | `--rental-only`, 문맥 4,096, `--gpu-layers 1`, 최대 출력 32토큰 |
| 전체 검사 시간 | 2026-09-19 03:51:51~03:54:20 UTC |

GPU 가용 메모리가 656 MiB여서 일부 레이어만 GPU에 배치했다. 전체 모델의 GPU 적재, 다른 물리 PC 간 실행, 인터넷 전송 성능은 이번 검증 대상이 아니다.

## 실제 실행 결과

일반 회원 인증으로 원시 GGUF를 업로드하고, 업로드 소유권을 확인한 정상 `chat` 요청을 생성했다. GPU 전용 제공자가 `renter-model` 기능을 알린 뒤 해당 lease에만 허용된 다운로드 경로로 별도 모델 사본을 받았다. 제공자는 파일 크기·SHA-256을 검증하고 GGUF에 포함된 채팅 템플릿으로 자신이 소유한 llama-server를 시작했다. 모델 선택·결과 제출을 우회한 가짜 응답은 사용하지 않았다.

- 입력: `Say hello briefly.`
- 실제 응답: `Hello! 😊 How can I assist you today?`
- 엔진 사용량: 입력 12토큰, 출력 12토큰. `finishReason: stop`.
- 작업: `completed`, 실행 단계: `settled`, 결과 구분: `generated`. 정답·인용 검증 성공을 뜻하지 않는다.
- 정산: 정상 영수증 생성, 사용 10 CR, 예약 0 CR. 임차인 잔액 100 → 90 CR.
- VRAM 관측: 시작 3,307 MiB → 최대 3,796 MiB → 종료 3,307 MiB. 증가량 489 MiB, 생성 구간의 GPU 사용률 표본 최대 39%.

응답 제출 전에 제공자가 소유한 실행 프로세스를 종료하고 모델 임시 폴더를 제거했다. 제공자 자체는 종료 코드 0으로 끝났다. 검사 후 업로드 원본을 삭제하고 격리 서버도 종료했다. 기존 프로세스는 유지했다.

로컬 증거는 `work/renter-real-smoke/report.json`, `runtime.log`, `provider.log`에 있다. 보고서에는 관리자 키·회원 키·노드 키를 넣지 않았다. GPU 수치는 약 2초 간격 표본이며 정밀 성능 벤치마크가 아니다.

## 자동 회귀 검사와 제한

`tests/model-artifacts.test.mjs`는 원시 HTTP 업로드, GGUF 헤더·해시·크기, 다른 회원의 접근 거절, 현재 lease에만 허용되는 다운로드, 취소·만료·폐기 후 거절, 중단 업로드 정리, 저장 한도, 삭제와 작업 생성의 동시 실행을 검사한다. `tests/chat-jobs.test.mjs`는 임차인 모델 계약, 결과 정산, 재시도·취소·실패 시 예약 해제, GPU 전용 자리표시 모델의 문서 작업 거절을 검사한다.

현재 경로는 **채팅 템플릿이 포함된 단일 GGUF**를 요청마다 제공자 GPU에 적재하고 추론 후 회수한다. 분할 GGUF, 임의 실행 코드, 임차인 지정 런타임, 상시 적재 배포 및 영속 API 엔드포인트는 지원하지 않는다. 다른 물리 PC와 실제 외부 제공자를 사용한 검증은 아직 수행하지 않았다.
