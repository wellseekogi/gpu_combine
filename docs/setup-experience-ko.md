# Relay 초기 설정 경험

사용자는 프로그램을 열고 파일을 선택한 뒤 참여를 시작할 수 있어야 한다. 파일 해시 계산, 연결 정보 전달, 추론 프로세스 실행과 중지, 작업 상태 조회는 프로그램이 처리한다. 명령줄은 운영·개발 또는 문제 진단을 위한 고급 경로로 남긴다.

## 이번 구현 범위

| 사용자 행동 | 자동으로 처리하는 일 | 남은 준비 |
|---|---|---|
| `START-RELAY.cmd` 더블 클릭 | 필요 시 의존성 설치·화면 빌드, 중앙 서버 시작, 기본 브라우저 열기, 로컬 일회용 로그인 | Node.js 22.13 이상 설치, 패키지 압축 해제; 소스 첫 실행은 인터넷 필요 |
| 웹 시작 안내에서 다음 단계 선택 | 체험·실제 연결의 차이와 설정 상태 안내 | 실제 연결에는 승인할 모델과 참여자 PC 필요 |
| 참여자 프로그램 다운로드 | GUI·제공자 실행 코드가 포함된 ZIP 제공 | Python 3.10 이상과 Tkinter 설치 |
| 실행파일·모델·템플릿 선택 | SHA-256 계산, 모델 계약 JSON 내보내기 | 신뢰하는 llama.cpp 빌드, GGUF, UTF-8 템플릿 준비 |
| 웹에서 계약 파일 불러오기 | 모델 해시·런타임 해시·템플릿 해시·문맥 길이 채우기 | 모델 이름과 필요 VRAM 확인, 운영자 승인 |
| 노드 승인 후 연결 파일 다운로드 | 중앙 서버 주소·풀·노드·인증키·승인 모델 계약을 한 파일에 담기 | 참여자에게 연결 파일 전달 |
| 연결 설정 저장·도우미에서 확인·시작 | 다운로드 폴더에서 연결 파일 찾기, 설정 검증과 제공자 실행, 추론 프로세스 관리 | 여러 연결 중 선택, 동일 모델 파일과 충분한 PC 자원 |
| 웹에서 진행 확인·참여자 창에서 중지 | 상태 자동 조회, 소유한 추론 프로세스 회수 | 실물 GPU에서 메모리 회수와 종료 동작 검증 필요 |

이 구현은 설치 이후의 명령 입력을 줄인다. Node.js·Python·GPU 드라이버·모델·런타임을 포함한 통합 설치 프로그램은 제공하지 않는다. 실제 GPU 추론 품질과 장비 호환성을 검증했다는 뜻도 아니다.

## 첫 방문 화면

첫 화면의 주 동선은 시작 안내다. 사용자는 다음 두 가지 중 하나를 선택한다.

- **체험:** 예제 문서를 불러오고 실행한다. 실제 GPU 연결 없이 서비스의 요청·상태·결과 흐름을 확인한다. 체험이라는 표시는 결과 화면까지 유지한다.
- **실제 GPU 연결:** 참여자 프로그램 준비 → 모델 승인 → PC 연결 → 작업 실행의 순서를 따라간다. 단계마다 현재 상태와 다음 행동을 보여 준다.

노드·원장·해시 같은 세부 개념을 처음부터 모두 입력하게 하지 않는다. 해시는 파일에서 가져오고, 연결 주소와 인증키는 연결 파일에 담는다. 수동 입력은 고급 경로로 유지한다. 재방문 시에는 기존 모델·노드·연결 상태에서 이어서 진행한다.

중앙 서버가 기본 로컬 주소로 실행 중이면 같은 PC에서만 쓸 수 있다고 안내한다. 이 주소가 들어 있는 연결 파일을 다른 PC에서 열어도 중앙 서버에 연결되지 않는다. 원격 참여자용 파일을 배포하기 전에 운영자는 `RELAY_PUBLIC_ORIGIN`과 TLS를 구성해야 한다.

## 운영자와 참여자의 흐름

처음 쓰는 사용자를 위한 용어는 다음처럼 안내한다.

- **모델:** Qwen처럼 AI가 학습한 가중치가 들어 있는 파일이다. 이 프로그램은 GGUF 형식을 실행한다.
- **llama-server:** 모델 파일을 읽고 이 PC에서 AI 연산을 수행하는 실행 프로그램이다.
- **모델 검증 파일:** 선택한 모델·실행 프로그램·템플릿이 같은 파일인지 확인하기 위한 정보다. 도우미의 **파일 검사 → 모델 검증 파일 저장**으로 만든다.
- **연결 파일:** 이 PC가 Relay에서 작업을 받기 위한 설정이다. Relay 주소, 등록된 PC 정보, 비밀 참여 키를 담는다. 웹에서 모델 승인과 PC 등록을 마친 뒤 **연결 설정 저장**으로 만들고 도우미에서 불러온다.

### 운영자

1. 중앙 서버를 실행하고 자동으로 열린 웹 콘솔에 접속한다.
2. 시작 안내에서 참여자 프로그램을 내려받는다.
3. 참여자 설정 창의 자동 탐색 목록에서 GGUF 모델을 선택한다. 내장 템플릿은 자동으로 준비되며, 실행파일과 나머지 누락 항목을 확인하고 **파일 검사** 후 **모델 검증 파일 저장**으로 `relay-model-contract.json`을 저장한다.
4. 웹에서 계약 JSON을 불러오고 이름·필요 VRAM을 확인한 뒤 모델을 승인한다.
5. 모델을 선택해 노드를 승인하고 해당 노드의 연결 파일을 내려받는다.
6. 참여자에게 연결 파일을 전달한 뒤 웹에서 노드의 연결 상태를 확인한다.
7. 실제 실행 화면에서 문서를 제출하고 진행·결과를 확인한다.

운영자와 참여자가 같은 PC를 쓰는 로컬 파일럿에도 같은 흐름을 적용한다. 이 단계의 “승인됨”과 “연결됨”은 별개다. 모델이나 노드가 등록된 것만으로 장비가 추론 준비를 마쳤다고 표시하지 않는다.

### 참여자

1. 참여자 ZIP을 풀고 `START-PROVIDER.cmd`를 더블 클릭한다.
2. 자동 탐색 목록에서 승인받은 GGUF 모델을 선택한다. 기본 위치에 없으면 **폴더 추가**를 누른다. 내장 템플릿은 자동 준비된다. llama-server도 자동 검색하며, 하나면 자동 선택하고 여러 개면 목록에서 고른다. 누락된 템플릿만 파일 선택 창으로 고른다.
3. 웹에서 연결 파일을 저장하거나 운영자에게 받은 파일을 참여자 PC의 다운로드 폴더에 둔다. 도우미가 첫 설정에서 하나를 찾으면 불러온다. 여러 개라면 서비스 주소와 PC 이름을 보고 선택한다. 다른 위치라면 **연결 폴더 선택** 또는 **연결 파일 불러오기**를 사용한다.
4. **검사하고 참여 시작**을 누르고 창의 상태와 로그를 확인한다.
5. GPU를 돌려받으려면 같은 창에서 **참여 중지**를 누른다. 창을 닫아도 앱이 소유한 작업 프로세스와 런타임을 종료한다.

처음 설정할 때는 연결 파일이 없어도 모델 준비를 진행할 수 있다. 모델 승인과 PC 등록을 마친 뒤 연결 파일을 발급한다. 도우미의 **연결 파일이 없나요? 웹 설정 열기**는 인증키를 입력하지 않아도 실제 연결 안내로 이동한다.

연결 파일 탐색은 특정 개발 PC의 경로에 의존하지 않고 배포 ZIP의 도우미에서 제공한다. Windows의 시스템 다운로드 폴더는 위치 변경을 반영하며, macOS Downloads와 Linux의 다운로드 폴더 설정도 사용한다. 브라우저별 사용자 지정 저장 위치는 **연결 폴더 선택**으로 지정할 수 있다. 도우미 실행 중 새로 저장한 파일도 찾지만, 기존에 저장하거나 수동으로 선택한 연결과 현재 실행 중인 연결은 자동으로 바꾸지 않는다. 파일 탐색과 불러오기는 GPU 참여를 시작하지 않는다.

자동 검색은 Windows·WSL의 표준 캐시와 일반적인 프로젝트 models 폴더, 사용자가 추가한 위치를 확인한다. 항목 수·깊이·시간을 제한하고 접근 거부나 일부 손상 파일이 있어도 다른 위치의 검색을 계속한다. 모델 이름·형식·용량·누락 여부를 표시한다. Transformers 형식은 현재 실행기에서 바로 실행할 수 없다고 안내한다. GGUF 선택 시 제한된 메타데이터만 읽어 내장 템플릿을 사용자 설정 폴더에 저장하며 모델 원본은 변경하지 않는다. 다운로드·변환·추론은 자동 시작하지 않는다.

참여자 설정 창은 선택한 모델·실행파일·템플릿·연결 파일과 추가 검색 폴더 경로를 사용자별 환경설정에 기억한다. Windows는 %LOCALAPPDATA%/Relay/provider-setup.json, 그 외 환경은 ~/.config/relay/provider-setup.json을 사용한다. 인증키는 환경설정에 복사하지 않으며 기존 연결 파일을 다시 검증해서 읽는다. 재실행 후에도 사용자가 참여 시작을 눌러야 연산을 시작한다. 파일이 없거나 환경설정을 읽지 못하면 재선택을 안내한다.

브라우저는 중앙 서버의 상태를 보여 주며 로컬 프로그램 실행은 참여자 앱이 맡는다. 브라우저가 참여자 PC의 임의 파일을 읽거나 로컬 GPU를 직접 실행할 수 있다고 안내하지 않는다.

## 진행·오류·재시도 원칙

아래 표는 UI가 지켜야 할 상태 설계 기준이다. 현재 범위에서 서버 요청의 로딩·실패 알림, 계약 입력 검증, 참여자 상태·로그, 작업 상태 자동 조회를 제공한다. 모든 실패를 전용 복구 화면으로 분류하거나 다운로드·해시 계산의 완료 예상 시간을 제공하는 기능은 후속 과제다.

| 상황 | 사용자가 알아야 할 내용 | 다음 행동 |
|---|---|---|
| 계약 파일 계산 중 | 어떤 준비 작업이 진행 중인지; 완료 전에는 중복 실행 방지 | 완료될 때까지 기다리기 |
| 파일 누락·형식 오류 | 잘못된 파일 또는 필수 항목을 특정; 이미 선택한 다른 파일은 유지 | 해당 파일 다시 선택 또는 계약 다시 가져오기 |
| 모델 계약 불일치 | 승인된 파일과 선택한 파일이 다름 | 승인된 실행파일·모델·템플릿 다시 선택 |
| 노드 승인 완료·아직 접속 전 | 등록은 완료되었지만 참여자 프로그램의 접속이 필요함 | 연결 파일 불러오기·참여 시작 |
| 연결 또는 인증 실패 | 중앙 서버 실행·주소·인증키 확인이 필요함 | 설정 수정 후 다시 시작; 폐기된 키는 노드 재승인 |
| 모델 적재 중 | 연결됨과 실제 실행 준비됨을 구분 | 준비 상태 또는 오류 확인 |
| 작업 실행 중 | 진행 상태를 자동 갱신; 수동 새로고침에 의존하지 않음 | 완료 기다리기 또는 승인된 중지·회수 동작 |
| 작업이나 앱 중지 중 | 종료 요청과 실제 종료 완료를 구분 | 프로세스 종료 확인 |
| 런타임 포트가 이미 사용 중 | 다른 프로그램의 포트를 자동으로 빼앗지 않음 | 기존 프로그램 종료 또는 고급 설정 확인 |
| 브라우저 자동 열기 실패 | 서버 주소와 수동 로그인 경로 제공 | 주소 열기·관리자 키로 로그인 |

재시도는 입력한 내용을 유지해야 하며 실패 원인을 숨기는 무한 로딩으로 처리하지 않는다. 실행 요청·계약 계산·중지 요청은 중복 클릭을 막는다. 수동 새로고침은 복구 수단으로 남길 수 있지만 정상 진행의 필수 단계로 만들지 않는다.

## 파일 계약

모델 계약 파일은 버전 `1`과 `modelDigest`, `runtime`, `template`, `context`를 갖는다. 세 파일 해시는 참여자 프로그램이 실제 선택 파일을 읽어 계산한다. 문맥 길이는 사용자가 선택하고 운영자가 확인한다. 해시 자체는 파일의 동일성을 비교하는 값이며 런타임의 안전성이나 추론 품질을 보증하지 않는다.

연결 파일은 최대 64KB이며 로컬 실행파일 경로를 자동 설정하지 않는다. 웹에서 내려받은 연결 파일에는 `coordinator`, `pool`, `node`, `token`, `context`와 승인 모델의 `digest`, `runtime`, `template`, `context`가 들어 있다. 새 파일은 선택용 PC 이름인 `nodeName`도 담으며 파일명은 `relay-provider-<PC ID>.json`이다. `nodeName`은 앞뒤 공백을 제거한 1~80자 문자열이고 제어 문자를 허용하지 않는다. 해당 필드가 없는 버전 1 파일과 기존 `relay-provider-private.json`도 계속 사용할 수 있다. 운영자가 발급한 노드와 모델에 연결되며 참여자 앱이 주소·파일 계약을 확인하는 데 사용한다. 인증키가 포함되므로 해당 참여자에게만 전달한다. 모델 계약 파일에는 노드 인증키가 없다.

자동 로그인은 기본 루프백 실행 시 발급하는 2분 유효·1회 사용 로그인 값을 이용한다. 공개 주소·보안 쿠키·비루프백 바인딩을 설정한 환경은 수동 관리자 로그인을 사용한다. 장기 관리자 키를 URL에 넣어 공유하는 흐름으로 사용하지 않는다. 수동 로그인은 자동 열기 실패 또는 별도 브라우저에서 재접속할 때 사용할 수 있다.

## 배포 전 필요한 후속 작업

## 검증 기준

- 새 데이터 폴더에서 중앙 서버를 실행해 브라우저가 열리고 로컬 자동 로그인 또는 명확한 수동 대안이 표시되는지 확인한다.
- 체험과 실제 연결의 설명·상태·결과가 섞이지 않는지 확인한다.
- 계약 JSON 불러오기와 연결 JSON 내보내기·불러오기가 동일한 모델·문맥·노드를 유지하는지 확인한다.
- 누락 파일, 잘못된 JSON, 해시 불일치, 만료·폐기 키, 서버 미실행, 이미 사용 중인 포트에서 재시도 행동이 가능해야 한다.
- 참여를 중지하거나 창을 닫을 때 앱이 소유한 런타임이 정리되는지 확인한다.
- 웹을 수동 새로고침하지 않아도 연결과 작업 상태가 갱신되는지 확인한다.
- 서로 다른 실제 GPU 장비에서 모델 적재·추론·회수와 원격 HTTPS 연결을 별도로 검증한다. 자동 테스트나 체험 결과로 대체하지 않는다.

이 문서의 검증 기준은 출시 전 확인할 항목이며, 모든 항목이 실장비에서 통과했다는 보고가 아니다. 실행 명령과 현재 검증 한계는 [README](../README.md)에 기록한다.

## 이번 변경의 확인 결과

Windows에서 전체 Python 테스트 103개, 설정 관련 Node 테스트 14개, 타입·린트·프로덕션 빌드를 통과했다. 분리된 로컬 서버와 Chrome에서 연결 안내 링크의 직접 이동, 자동 로그인 및 URL 인증값 제거, 잘못된 계약 파일 복구, 모델 승인, PC 등록, 연결 JSON·도우미 ZIP 다운로드, 390px 화면 가로 넘침 없음, 실제 연결에서 체험으로 전환, 로그아웃·재로그인 사이에 지연된 설정 응답 차단을 확인했다. 브라우저 콘솔 오류는 없었다.

실제 PC에서 WSL로 사용하던 Qwen3-4B Instruct·Thinking GGUF 두 개와 Windows Hugging Face 캐시 두 개를 자동 탐색했다. GUI에서 Instruct 선택 후 내장 템플릿이 정확한 UTF-8 바이트로 준비되고, Transformers 형식은 선택이 제한되며, 모델 선택만으로 런타임이 시작되지 않는 것을 확인했다. 테스트는 임시 환경설정 폴더를 사용했다. 680×600 창에서도 하단 작업 버튼이 표시된다. 검색 시간 제한·누락 파일·분할 GGUF·WSL 파일 응답 지연·템플릿 읽기 실패를 자동 테스트에 포함했다.

실행 중인 로컬 서비스의 도우미 ZIP에 검색기와 템플릿 모듈이 포함된 것을 확인하고 새 설정 창을 실행했다. 이후 사용자 요청으로 공식 llama.cpp b10964 Windows CUDA 12.4 실행기와 CUDA 라이브러리를 내려받아 릴리스 SHA-256과 대조했다. RTX 3050 Ti 4GB에서 기존 Qwen3-4B Instruct Q3_K_M, 문맥 8192로 실제 추론을 확인했고, 도우미와 동일한 작업 프로세스로 Relay의 실제 작업 1건을 완료했다. 제품명·메모리 두 항목의 인용 검증을 통과했다. 적재 시 GPU 메모리는 약 3307MiB였으며 중지 후 사용량 0MiB와 프로세스 종료를 확인했다. Windows SYSTEMROOT 환경변수 전달 및 도우미의 subprocess 상수 누락도 수정했다. 이는 이 PC에서의 한 건 검증이며 다른 장비·장시간 부하·원격 TLS 검증을 의미하지 않는다. 설치된 WSL vLLM 연동과 일반 사용자용 자동 설치 버튼은 별도 범위다.


### 공통 연결 파일 자동 감지 검증

특정 PC 경로 없이 사용자별 다운로드 위치를 기준으로 동작한다. 새 다운로드를 주기적으로 확인하고, 유효한 연결이 하나인 초기 설정에서 자동으로 불러온다. 여러 연결, 기존 수동 입력, 이전 연결 파일의 누락·손상 상태에서는 사용자가 선택한다. PC 이름은 선택적 표시 정보로 내보내며 기존 이름 없는 연결 파일도 지원한다.

숨김 Tk UI 테스트 12개로 자동 가져오기, 실행 중 새 파일 감지, 복수 후보 선택, 기존 설정 보존, 불완전 검색의 재시도 제한, 지연된 네트워크 파일 읽기 이후 복구를 검증했다. 파일 읽기가 지연돼도 창이 응답하며 늦게 끝난 읽기가 새 선택을 덮어쓰지 않는다. 검색이 불완전하면 자동 반복을 멈추고 연결 폴더 선택 또는 다시 찾기를 안내한다. GPU 실행은 기존 참여 시작 버튼을 사용한다.

Windows 다운로드 Known Folder는 실제 조회를 확인했고, 다른 사용자 홈·리디렉션 경로·macOS 기본 위치·Linux XDG 설정은 격리된 경로 테스트로 확인했다. 브라우저에서 PC 이름과 표준 파일명이 포함된 연결 파일 및 새 모듈이 포함된 도우미 ZIP을 내려받는 흐름을 검증했다. 현재 서비스의 ZIP에도 같은 공통 기능이 포함되어 있다. 이전에 내려받은 도우미는 최신 ZIP으로 갱신해야 한다.
