# 두 PC의 Codex로 Relay LLM 성능 검증하기

작성: 2026-09-24. 이 파일은 두 Codex에 전달하는 공통 맥락과 복사할 프롬프트다. 이 파일을 만드는 것만으로 작업 공간 생성이나 GPU 테스트가 실행되지는 않는다.

## 1. 같은 작업 공간이라는 뜻

Agent Relay 작업 공간은 **두 Codex가 들어가는 공용 대화방과 수신함**이다. 같은 서버의 **같은 workspace key**를 사용해야 한다. 두 PC에서 이름만 같게 만들어도 서로 다른 방이다.

| 구분 | 하는 일 |
|---|---|
| Agent Relay 작업 공간 | Codex끼리 준비 상태, 테스트 지시, 결과를 전달 |
| 각 PC의 프로젝트 폴더 | 각 Codex가 실제 파일을 읽고 명령을 실행하는 곳. 자동 공유되지 않음 |
| 사용자 프로젝트 Relay의 LLM 실행 공간 | GPU 실행 그룹을 예약하고 `/v1/workspaces/<id>/chat/completions`로 모델을 호출하는 곳 |

Agent Relay를 연결해도 모델·소스·GPU 메모리가 합쳐지지 않는다. 소스와 실행 파일은 필요한 PC에 별도로 준비한다. **사용자는 작업 공간에 명령을 쓰는 것이 아니라 각 PC의 Codex 대화창에 아래 프롬프트를 보낸다.**

이 문서에서 A는 현재 프로젝트가 있는 PC, B는 다른 데스크탑이다. AWS는 별도의 중앙 서비스다. 기존 AWS 검증 문서의 A/B 표기와 혼동하지 않는다.

## 2. 사용 순서

1. 이 파일을 양쪽 Codex에 첨부하거나 각 PC에서 읽을 수 있는 위치에 둔다.
2. A의 Codex에 **프롬프트 A**를 보낸다. A가 연결용 비공개 JSON 파일을 만든다.
3. 사용자가 그 JSON 파일을 B에 직접 복사한다. 파일은 사용자 홈의 `.agent-relay/gpu-together-join.json`에 두면 된다. 다른 위치라면 B에게 경로를 알려준다. workspace key를 채팅에 붙이지 않는다.
4. B의 Codex에 **프롬프트 B**를 보낸 뒤, A의 Codex에 **프롬프트 C**를 보낸다.

최초 연결 이후에는 같은 파일과 작업 공간을 재사용한다. 다른 방을 매번 새로 만들지 않는다. 이 안내 파일은 공유해도 되지만 연결 JSON은 자격 증명이므로 공개·Git 커밋·보고서 첨부 대상이 아니다.

**설정하는 Codex의 사전 확인:** MCP는 작업 공간 키를 프로젝트의 `.agentworkforce/relay/workspace-key.json`에도 저장할 수 있다. 첫 생성/연결 호출 전에 `git rev-parse --git-path info/exclude`가 가리키는 로컬 제외 파일에 `/.agentworkforce/relay/`가 포함되도록 기존 내용을 보존해 추가하고, `git check-ignore .agentworkforce/relay/workspace-key.json`으로 확인한다. Git 저장소가 아니면 파일을 비공개 작업 폴더에 유지한다. 연결 도구의 현재 세션에는 파일 복사만으로 key가 적용되지 않으므로 `set_workspace_key`도 호출한다.

### 프롬프트 A — 현재 PC: 연락방 준비

```text
$agent-relay를 사용하고 첨부한 AGENT-RELAY-TWO-PC.md를 읽어 줘.
너는 현재 PC에서 gpu_togeter 프로젝트의 테스트를 총괄하는 Codex다.
이번 턴에는 두 PC가 쓸 Agent Relay 연락방과 연결 파일만 준비해 줘.

1. 먼저 이 문서의 key 파일 Git 제외 절차를 확인해.
   이 프로젝트용으로 이전에 저장한 작업 공간이 있으면 그것을 재사용해.
   관계없는 전역 활성 작업 공간을 임의로 재사용하지 말고, 이 프로젝트용이 없으면 하나만 만들어.
   Agent Relay 공간이며 프로젝트의 LLM/GPU 실행 공간을 만드는 단계는 아니야.
2. key를 설정한 후 이미 실행 중인 네 Codex를 relay-lead라는 이름으로 등록해.
   실제 반환된 등록 이름을 확인하고 이후에는 그 이름을 사용해. add_agent로 새 Codex를 띄우지 마.
3. 같은 방에 B가 들어올 수 있도록 서버 주소, 공용 workspace key, 실제 lead 이름을
   사용자 홈의 .agent-relay/gpu-together-join.json에 저장해.
   필드 이름은 base_url, workspace_key, lead_agent를 사용해.
   기존 파일이 있으면 같은 프로젝트의 것인지 확인하고 유효한 key를 덮어쓰지 마.
4. key를 대화나 로그에 출력하지 말고, 내게 복사할 파일 경로만 알려 줘.
   개별 agentToken이나 전체 Codex 설정은 연결 파일에 넣지 마.
   도구가 프로젝트 안에 자동 저장하는 key 파일도 Git에 들어가지 않게 확인해.
5. GPU나 모델은 아직 시작하지 말고 연결 준비 완료로 마무리해.

설치된 Windows MCP 설정을 재사용해. Bash 자동 설치 스크립트나 작업 승인 정책을 바꾸지 마.
도구가 현재 세션에 보이지 않으면 실제 MCP 연결 상태를 확인하고 필요한 재시작만 안내해.
```

### 프롬프트 B — 다른 데스크탑: 같은 방 참여 및 GPU 준비

```text
$agent-relay를 사용하고 첨부한 AGENT-RELAY-TWO-PC.md를 읽어 줘.
너는 이 데스크탑에서 GPU 상태와 LLM 실행을 담당하는 Codex다.
검증 대상은 내 Relay 프로젝트의 실제 LLM 토큰 생성 속도다.

1. 사용자 홈의 .agent-relay/gpu-together-join.json을 읽어.
   내가 다른 경로를 지정했다면 그 파일을 사용해.
   파일이 없으면 필요한 경로를 알려 주고, 새 workspace를 만들지 마.
2. 이 문서의 key 파일 Git 제외 절차를 확인한 뒤,
   파일의 base_url과 workspace_key로 기존 방에 연결하고,
   현재 실행 중인 너를 relay-desktop으로 등록해. 실제 반환된 이름을 사용해.
   key나 agentToken을 출력하지 말고, 자동 저장된 key 파일도 Git에서 제외해.
3. 파일의 lead_agent에게 ACK를 보내 네 실제 등록 이름과 담당 역할을 알려 줘.
4. OS, GPU/VRAM, 사용 가능한 모델·GGUF 해시, llama.cpp 실행 파일·버전,
   프로젝트 폴더/제공자 프로그램 유무를 조사해 비밀값 없이 lead에게 보내.
   이전 대화나 이 문서의 예시로 하드웨어·버전·모델 경로를 추정하지 마.
5. 이 문서의 공통 실행 범위 안에서 lead의 테스트 요청을 처리해.
   모델 실행 전에는 사용할 모델·옵션·측정 구간을 lead와 맞추고 READY를 보내.
   초기 조사는 계속하되 측정 시작은 lead의 RUN 메시지와 맞춰.
6. 활성 작업 중 수신함을 15~30초 간격과 주요 단계가 끝날 때 확인해.
   메시지를 받은 뒤 ACK, 진행 중 STATUS, 끝나면 근거를 포함한 DONE을 보내.
   초기 연결 대기는 최대 10분이고, 테스트는 lead가 정한 종료시각까지 진행해.
   종료시각에 정리가 진행 중이면 내가 시작한 프로세스를 먼저 안전하게 정리해.

폴더나 모델이 없으면 필요한 항목을 lead에게 구체적으로 요청해.
설치만 된 것으로 통신 성공을 주장하지 말고 실제 메시지 교환을 확인해.
```

### 프롬프트 C — 현재 PC: 테스트 지휘 시작

```text
$agent-relay를 사용하고 AGENT-RELAY-TWO-PC.md의 공통 맥락과 측정 기준을 따라 줘.
이전 연결 JSON의 같은 작업 공간과 lead_agent 이름을 재사용해.
수신함에서 데스크탑의 ACK와 실제 등록 이름을 확인하고 그 상대와 진행해.

목표는 내 Relay 프로젝트가 다른 데스크탑의 GPU에서 실제 LLM을 실행하는지,
그리고 생성 속도가 얼마나 되는지를 재현 가능한 수치로 검증하는 거야.

1. 양쪽의 런타임·모델·프로젝트 버전을 대조하고 run_id를 만들어 공유해.
   현재 작업 트리의 미커밋 변경과 배포 버전 차이도 확인해.
2. 우선 원격 GPU에서 실제 요청 1건의 실행·응답·GPU 사용 증거를 확인해.
3. 가능하면 같은 모델·생성 조건으로 데스크탑 엔진 직접 호출과
   실제 Relay 서비스를 통한 원격 호출을 각각 워밍업 1회 + 측정 5회 비교해.
   같은 GPU의 두 시험은 순차 실행해. 실제 출력 토큰 수와 캐시 상태를 기록해.
4. 현재 분산 실행 경로의 필수 조건이 갖춰졌으면 동일 모델의 단일 GPU와
   두 PC 레이어 분할도 비교해. 조건이 없으면 부족한 항목을 적고 NOT RUN으로 남겨.
   다른 모델이나 다른 양자화의 속도를 같은 조건의 향상률로 비교하지 마.
5. 엔진 생성 tokens/s, 서비스 전체 소요시간, 관측 가능한 첫 출력 지연,
   GPU별 peak VRAM, 성공/실패를 기록해. Codex와 Relay 메시지 대기 시간은 빼.
6. 측정 시작부터 총 30분 안에 끝나는 기본 범위로 진행하고 종료시각을 B에 알려 줘.
   기존 실행기와 측정 도구를 우선 사용하고, 부족한 계측만 작은 스크립트로 보완해.
   필요한 준비가 끝나면 매 단계 사용자 확인을 반복하지 말고 B와 협의해서 진행해.
7. work/agent-relay-benchmark/<run_id>/에 비밀값을 제거한 원시 측정 결과와
   report.md를 저장해. B의 파일은 자동 공유되지 않으니 필요한 요약과 증거를 받아.
   테스트가 만든 프로세스·예약을 정리한 뒤 B에게도 종료와 정리를 확인해.

관측한 사실, 실패, 미실행을 분리하고 마지막에 실제 수치와 다음 병목을 설명해 줘.
```

## 3. 두 Codex가 공유할 프로젝트 맥락

- 프로젝트 이름은 **Relay / gpu_togeter**다. Agent Relay는 연락 도구이고, 이 프로젝트 Relay는 GPU 제공·모델 실행 서비스다.
- 현재 PC의 저장소 경로는 `C:\gpu_togeter`다. B의 경로는 직접 확인한다. 로컬 미커밋 변경이 있으므로 Git commit이 같다는 사실만으로 파일이 같다고 보지 않는다. 필요한 실행 파일과 변경 파일의 버전/해시를 비교한다.
- README에 기록된 중앙 서비스 주소는 `https://gpu-together.3.38.50.72.sslip.io`다. 현재 접속 가능 여부와 배포 버전은 테스트 때 확인한다. 이 문서 작성으로 접속 성공이 확인된 것은 아니다.
- 모델은 GGUF, 추론 엔진은 llama.cpp 계열이다. 웹에서 다른 GPU에 모델을 업로드·임대하여 대화하는 경로와, 여러 GPU의 연속 레이어 분할로 하나의 모델을 실행하는 경로가 있다. 기존 문서 추출 worker는 별도 경로다.
- 분산 경로는 `provider/distributed_runtime.py`, `lib/relay/inference.mjs`, `lib/relay/inference-plan.mjs`와 관련 문서를 기준으로 확인한다. 자동화 테스트의 가짜 backend 성공은 GPU 성능 증거가 아니다.
- 현재 분산 실행 문서는 b10964 소스 계열 및 실제 RPC/GPU 지원 빌드를 요구한다. 두 PC의 설치 상태가 이 조건을 충족하는지 확인한다. Agent Relay 연결 자체가 llama.cpp RPC 사설망을 마련해 주지는 않는다.
- B에 전체 저장소가 없어도 설치 상태와 GPU 조사는 진행할 수 있다. 실행 코드가 필요하면 A에게 필요한 파일 목록을 요청한다. Agent Relay에 참여했다고 소스나 모델이 자동으로 생기지는 않는다.
- 두 Codex가 직접 파일을 수정해야 한다면 담당 파일을 먼저 나누고 테스트용 보완에 한정한다. 이 작업은 서비스 재설계나 성능 개선을 완료했다고 주장하는 작업이 아니다.

소스가 있는 PC에서 읽을 참고 자료:

| 자료 | 사용할 부분 |
|---|---|
| `README.md` | 현재 서비스 진입점과 실행 경로 |
| `docs/distributed-inference-ko.md` | 분산 실행 준비, RPC 조건, 스트리밍 동작, 측정 조건 |
| `docs/distributed-workspace-design-ko.md` | LLM 실행 공간과 성능 선언 계약 |
| `docs/handoffs/AWS-REMOTE-GPU-CODEX.md` | 다른 PC의 프로그램 준비·GPU 계측·정리 절차 |
| `docs/reports/renter-model-validation-ko.md` | 과거 검증의 증거 형식과 한계 |

과거 AWS 문서의 문서 추출 작업·요금·일시 임대 조건을 현재 채팅/지속 임대 API에 그대로 대입하지 않는다. 최신 로컬 코드와 실제 배포 API를 확인하며, 필요한 자료가 B에 없으면 A가 관련 부분을 전달한다.

## 4. 실행 범위와 측정 기준

위 실행 프롬프트는 장비 조사, 기존 프로그램/모델을 사용한 테스트 준비, 테스트 전용 설정·계측 스크립트, 양쪽 메시지 교환, 모델 적재와 요청 실행, 결과 저장·정리를 지시한다. 새 유료 자원 생성, 운영 서버 배포·DB 변경, 드라이버 교체, 기존 타 작업 강제 종료는 포함하지 않는다. 모델이나 실행 파일이 없어 별도 대용량 다운로드가 필요하면 파일·크기·출처를 먼저 정리한다.

llama.cpp RPC는 격리된 LAN 또는 인증·암호화된 사설 연결에서만 준비한다. Agent Relay 메시지에 서비스 관리자 키, 계정 복구 키, workspace key, Authorization 헤더를 싣지 않는다. 두 PC는 각자 로컬 자격 증명을 사용하며 공개 테스트 프롬프트와 필요한 최소 측정 정보만 교환한다.

| 측정 항목 | 기준 |
|---|---|
| 엔진 생성 tokens/s | 엔진이 실제 생성한 출력 토큰 수와 생성 구간 시간을 사용. 엔진 제공값이면 필드와 정의도 기록 |
| 서비스 전체 소요시간 | 클라이언트의 요청 시작부터 정상 응답/스트림 완료까지. 같은 PC의 단조 증가 시계로 측정 |
| 첫 출력 지연 | 엔진 내부 첫 출력과 클라이언트가 관측한 첫 출력을 구분. 측정할 수 없으면 N/A |
| 전체 요청 기준 tokens/s | 출력 토큰 수 ÷ 전체 요청 소요시간. 엔진 생성 tokens/s와 별도 이름으로 기록 |
| GPU 증거 | GPU 식별자, 해당 런타임 PID, 적재/실행 로그, VRAM 기준값·최대값·정리 후 값 |

문자 수나 SSE 조각 수를 토큰 수로 사용하지 않는다. 실제 출력 토큰 수, 모델/템플릿 해시, 엔진 버전, 입력 내용과 입력 토큰 수, 출력 상한, 문맥 크기, GPU 분할/오프로딩, 동시성, 캐시·세션 상태를 함께 기록한다. 모델 적재 시간과 워밍업은 정상 생성 구간과 분리한다. 토큰 생성이 일찍 종료되면 실제 출력 길이를 기록한다.

**LLM 실행 공간의 기본 SSE는 응답을 완료 후 모아서 전달한다.** 이때 클라이언트의 조각 도착 간격으로 엔진 생성 속도를 계산하면 안 된다. 엔진 로그/계측을 사용하거나, 실제 구현의 `stream:true, restart_on_failure:true` 동작을 확인하고 `relay.restarting`/`relay.completed`를 처리한다. 재시도가 있으면 실패 시도와 성공 시도를 분리하고 전체 서비스 시간에는 재시도 비용을 포함한다.

기본 측정 5회는 중앙값과 범위, 각 원시 샘플을 보고한다. 적은 표본으로 신뢰할 만한 p95나 일반적인 성능 향상을 단정하지 않는다. 같은 모델이 단일 GPU에 들어가지 않으면 해당 baseline은 NOT RUN이며, 다른 작은 모델로 바꿔 speedup을 만들지 않는다.

## 5. 메시지와 재개

각 메시지에는 동일한 `run_id`와 단계 이름을 넣는다. lead와 desktop은 **등록 도구가 실제 반환한 이름**으로 메시지를 주고받는다.

```text
ACK    run_id=... phase=inventory  역할과 요청 확인
READY  run_id=... phase=remote    모델/설정 확인, 측정 준비 완료
RUN    run_id=... phase=remote    lead가 시험 조건과 실행 순서 전달
STATUS run_id=... phase=remote    5회 중 2회 완료, 관측한 오류 없음
DONE   run_id=... phase=remote    실제 샘플 수, 결과 요약, 로컬 증거 경로
BLOCKED run_id=... phase=split    RPC 지원 실행 파일 없음; 확인한 근거
```

`DONE`의 경로는 그 PC의 로컬 경로다. 상대가 읽을 수 있다고 가정하지 않는다. 비밀값을 제거한 작은 JSON/CSV는 메시지 또는 도구가 지원하는 파일 전달로 공유하고, 큰 파일은 원래 PC에 보존한다.

설치와 에이전트 등록은 대기 중인 Codex 대화를 자동으로 깨우지 않는다. 한쪽이 대화를 끝냈다면 해당 PC의 같은 Codex 대화에 아래 문장을 보내 재개한다.

```text
기존 Agent Relay 작업 공간과 내 등록 이름을 재사용해.
수신함에서 마지막 run_id의 미완료 요청을 확인하고 이어서 처리해.
새 방이나 새 에이전트를 만들지 말고, 완료된 측정을 중복 실행하지 마.
```
